# 2.24.0 · Codex 펌웨어 생성 · BOM 설계 · CAD 파일 연결

회로도에서 등록한 정확한 보드·핀·전선과 원하는 동작을 바탕으로 코드 후보를 생성합니다. 기존 ChatGPT 구독의 Codex 연결을 사용합니다. 기존 코드 업로드·배선 추적·DC 안전 점검도 유지합니다.

메인 AI 패널의 **BOM 보고 설계…**에서 CSV/TSV/XLSX 또는 붙여넣은 부품표를 검토하고 AI 설계 입력으로 저장합니다. 실제 부품의 수량·명시 치수·제품 정보는 **미리보기 → BOM 대조**에서 비교합니다. [BOM 사용법](BOM_DESIGN_KO.md)을 참고하세요.

새 프로젝트의 기본 확장자는 `.pcad`입니다. `Install.ps1`은 바탕화면 바로가기와 전용 파일 열기 연결을 등록합니다. 기존 기본 앱 선택과 일반 `.json` 연결은 보존합니다. 이전 `.cad.json`도 계속 읽으며, 이미 열어 둔 파일에 일반 저장을 하면 그 경로를 유지합니다. `.pcad`로 이름을 바꾼 파일의 옛 경로도 같은 폴더에서 찾아 엽니다. [파일 연결 안내](FILE_ASSOCIATIONS_KO.md)를 참고하세요.

## 여는 곳

상단 **선택 부품 색상 옆 회로도 메뉴 → Codex 펌웨어 생성 / 검토…** 또는 **전장 작업창 → 같은 이름의 버튼**을 누릅니다. 빈 설계에서는 먼저 CAD 부품을 정확한 보드 제품으로 전장에 등록해야 합니다. 제품군만 정했거나 핀을 임의로 입력한 부품은 생성 대상이 아닙니다.

1. 등록한 보드를 선택합니다. 보드에 대응하는 STM32 HAL, Arduino 또는 Raspberry Pi Python 형식만 표시됩니다.
2. 연결을 확인하고 현재 계정이 반환한 Codex 모델·추론 강도를 고릅니다. 모델 선택만으로 생성 요청을 보내지 않습니다.
3. 원하는 동작을 적고 코드를 생성합니다. 메인 AI 창의 대기 시간 설정을 사용합니다. 무제한이면 검증 수정도 계속하며, 통신 단절은 재연결을 기다립니다. 로그인·사용량 문제는 무한 재요청하지 않습니다.
4. **코드 미리보기 / 편집**, **핀 / 배선**, **미정 값 / 검토 / 빌드 결과**를 확인합니다.
5. **코드 변경 전체 저장**을 누르면 CAD 프로젝트에 보관합니다. 전장 작업창에서 열었다면 바깥 작업창도 저장해야 실제 설계에 반영됩니다. 바깥 작업창에서 취소하면 안쪽 저장을 포함한 변경이 취소됩니다.

메인 AI 창에서 첨부한 GitHub·파일 참고자료도 생성 요청에 전달합니다. 읽어 온 텍스트와 출처만 참고하며 링크를 자동 탐색하거나 자료 속 코드를 실행하지 않습니다. 자료가 한도를 넘으면 설명을 표시하고 전송을 중단합니다.

## 생성 요청 예

> 선택한 보드의 저장된 배선을 기준으로 피로시험기 제어 코드 초안을 만들어줘. 시작은 정지 상태로 하고, 준비·운전·고장 상태를 분리해줘. 비상정지, 피드백 끊김, 시간 초과는 정지 상태를 유지하며 명시적으로 초기화해야 다시 준비할 수 있게 해줘. 현재 미정인 모터·엔코더·하중 교정·이동거리·주파수는 만들어내지 말고 설정 항목으로 남겨줘. 가상 데이터와 실측 데이터를 구분하고 물리적 초·Hz 단위를 써줘. 보드 SDK와 장비 어댑터가 없는 부분은 미구현으로 표시해줘.

보드 데이터가 MCU 내부 회로까지 제공한다는 뜻은 아닙니다. **B-G431B-ESC1**은 확인된 외부 커넥터만 제공합니다. 내부 GPIO·타이머·MCSDK·모터 파라미터를 추정해 실제 FOC 코드를 완성했다고 표시하지 않습니다.

## 저장과 재검토

여러 소스 파일과 설명서, 생성 요청·모델·UTC 시각, 보드·배선 연결 정보, 소스 SHA를 `.pcad`에 함께 저장합니다. 외부 소스 폴더 없이 프로젝트를 다시 열 수 있습니다. 일반 작업 기록과 실행 취소·복원에 포함됩니다. 기존 파일의 색상·치수·작업 기록을 덮어쓰지 않습니다.

작업창에서 다른 보드나 저장 코드를 선택해도 편집 내용은 작업창 안에 남습니다. 저장 버튼은 변경한 코드를 함께 검토해 전체 반영합니다. 연결 해제도 저장해야 반영됩니다. 보드나 배선을 바꾸면 이전 코드를 삭제하지 않고 현재 회로와 다른 상태로 표시합니다. 현재 배선으로 재생성한 후 다시 검토해야 합니다.

핀 검사는 확인 가능한 상수와 GPIO API 호출을 대조합니다. 임의 동적 표현식·SDK 내부·실행 경로까지 증명하지 않습니다. 수동 편집 후 이전 문법 검사 결과는 무효화되며 다시 검사해야 합니다.

코드 보관 한도는 프로젝트당 16개 묶음, 묶음당 32파일·2 MiB, 파일당 UTF-8 256 KiB입니다. **이 한도는 코드 첨부에만 적용되며 CAD 프로젝트의 이전 32 MB 저장 제한과 다릅니다.**

## 소스 검사와 내보내기

**빌드 / 소스 확인**에서 Python 문법을 코드 실행·import 없이 검사합니다. 설치된 GNU/Clang C/C++ 컴파일러 경로를 직접 지정하면 고정된 문법 검사만 수행합니다. SDK 헤더·도구가 없으면 필요한 조건을 표시합니다. 문법 통과가 보드 전체 빌드·링크·실물 동작 통과라는 뜻은 아닙니다. 생성한 빌드 스크립트·업로드 명령을 실행하지 않습니다.

**새 폴더로 내보내기…**는 소스와 연결 정보를 새 폴더에 함께 저장합니다. 기존 폴더를 덮어쓰지 않고 중간 실패·취소 시 불완전한 결과 폴더를 공개하지 않습니다. 확인이 끝난 뒤 실제 보드의 IDE·SDK 프로젝트에 가져가 대상 빌드와 장비 시험을 진행하세요.

## 검증 범위

실제 구독 Codex에 소유한 Raspberry Pi 4 보드·GPIO18 전선 시험 자료를 보내 소스 5개와 README를 받았습니다. 핀 대조·Python 문법·프로젝트 저장/재열기·실행 취소/복원·원자적 내보내기를 확인했습니다. 생성 코드는 실행하지 않았고 유료 API·하드웨어를 사용하지 않았습니다.

실제 구독 BOM 설계는 첫 시도에서 17.125초에 흰색 판재 2개를 만들었습니다. 각각 60×35×4 mm이고 부품 사이 실측 간격은 100 mm였습니다. 수량·치수·행 연결·4단계 작업 기록과 저장/재열기를 확인했습니다. 이 시험이 모든 BOM이나 실물 제조 적합성을 보장하지는 않습니다.

최종 소스·Windows EXE의 검증 수치는 [검증 기록](native2240-validation.json)에 제공합니다. 전체 펌웨어·Linux·FOC 에뮬레이션, 실제 장비 구동, 하중·주파수·왕복거리 정격 승인은 포함하지 않습니다.

처음 설치할 때는 릴리스의 Windows ZIP을 설치합니다. 기존 설치는 `PromptCADStudioUpdater.exe`로 같은 경로를 갱신합니다. 열려 있는 CAD 작업을 저장하고 앱을 모두 종료한 뒤 업데이트하세요.
