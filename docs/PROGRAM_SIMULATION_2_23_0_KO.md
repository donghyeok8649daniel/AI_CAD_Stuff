# 코드와 배선 자동 추적

전장 작업창의 **코드 · 배선 시뮬레이션**에서 소스를 업로드하면 추가 매핑 설정 없이 등록된 정확한 보드 모델, 코드의 실제 GPIO, 저장된 노드와 닫힌 전선을 찾아 10초의 신호 명령을 추적합니다. 전장에 보드가 여러 개 있으면 해당 CAD/전장 부품을 먼저 선택합니다. 보드·핀·전원·수신 단자 중 하나라도 확인되지 않으면 원인을 표시합니다.

소스는 프로젝트에 파일명, UTF-8 내용과 SHA-256으로 첨부됩니다. 파일당 최대 256 KiB이며 외부 파일을 옮겨도 첨부 내용은 유지됩니다. **프로그램 첨부 적용**과 바깥 전장 창의 저장을 완료해야 프로젝트에 반영됩니다. 취소하면 회로·CAD 형상은 변경되지 않습니다.

지원하는 명령:

- Arduino: 상수 핀과 `setup()/loop()`, `pinMode(..., OUTPUT)`, `digitalWrite`, `analogWrite`(0~255), `delay`.
- Raspberry Pi Python: `RPi.GPIO`의 BCM/BOARD 번호, 출력 모드, 출력, PWM 생성·시작·duty 변경·정지, `time.sleep`; `gpiozero`의 LED/PWMLED/OutputDevice on/off/value. 마지막 `while True`와 정적 `range` 반복.
- STM32: 문서에 있는 헤더 GPIO의 `HAL_GPIO_WritePin`, `HAL_GPIO_TogglePin`, `HAL_Delay`를 단일 `main(void)`의 마지막 `while(1)`에서 추적.

지원하지 않는 코드를 건너뛰어 성공으로 표시하지 않습니다. GPIO 입력, 엔코더 읽기, 통신, 인터럽트, 동적 분기, 라이브러리 내부, 타이머 핀 선택, 전체 C 프로젝트, ELF/HEX, Linux/실제 MCU 실행은 이 도구의 범위가 아닙니다. STM32 GPIO 초기화나 PWM 주파수가 소스 추적에서 검증되지 않으면 확인 필요로 표시합니다.

출력 추적에서는 HIGH→GND, 같은 배선의 서로 다른 출력, 외부 전원→GPIO, GPIO→모터 전력 단자, 수신 MCU보다 높은 논리 전압을 경고합니다. 실제 핀별 최대 입력과 5 V tolerant 여부, 출력 전류·모터 동작·온도는 별도 모델/데이터로 평가해야 합니다. 기본 전장 DC/열 안전 계산과 모터·엔코더 축약 해석은 별도 결과입니다. **신호 추적 완료는 하드웨어 구동 또는 안전 인증이 아닙니다.**

업로드 소스는 컴파일하거나 `eval`, 쉘, Python 실행, 보드 업로드로 실행하지 않습니다. 실제 부품이나 네트워크에 명령을 보내지 않습니다. 반복·표시 개수·계산 시간을 제한하고 취소할 수 있습니다.
