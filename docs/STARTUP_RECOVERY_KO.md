# 실행 직후 종료 · 그래픽 시작 복구 (2.10.1)

Windows OpenGL 초기화가 실패하면 파이썬 예외 대신 메모리 접근 위반으로 프로세스 자체가 종료될 수 있습니다. 2.10.1은 실제 3D 프레임을 별도 검사 프로세스에서 먼저 렌더링합니다.

- 기본 그래픽 드라이버 검사에 성공하면 GPU를 사용합니다.
- 실패·강제 종료·20초 응답 지연이 발생하면 앱에 포함된 Mesa 소프트웨어 렌더러를 검사해 전환합니다. 시스템 그래픽 DLL이나 드라이버는 변경하지 않습니다.
- 소프트웨어 모드에서는 상태 표시줄에 **소프트웨어 3D · 안정 모드**가 나타납니다. 형상 계산·저장·내보내기는 같지만 복잡한 모델의 화면 표시 속도는 낮아질 수 있습니다.
- 두 방식 모두 실패하면 설계를 열지 않은 상태로 **그래픽 시작 복구** 창을 띄웁니다. 검사 재시도·진단 폴더 열기·진단 내용 복사가 가능합니다.
- **도움말 → 그래픽 시작 진단**에서 현재 렌더러와 검사 결과를 확인합니다.

기본 진단 위치는 `%LOCALAPPDATA%\PromptCADStudio`입니다. `graphics-status.json`, `graphics-hardware*.log`, `graphics-software*.log`, `native-desktop.log`에 검사 결과와 시작 단계/네이티브 오류를 기록합니다. 자동저장 프로젝트는 변경하지 않습니다. 로그에는 설계 프롬프트나 API 키를 넣지 않습니다.

필요한 경우 `PromptCADStudio.exe --renderer software`로 소프트웨어 렌더러를 직접 선택할 수 있습니다. 평상시에는 인자 없이 실행하면 됩니다. 이 수정은 재현한 그래픽 시작 충돌을 처리하며 모든 드라이버 결함이나 실행 중의 모든 네이티브 충돌을 보장해서 막는 기능은 아닙니다.

렌더러는 [Qt 공식 Windows 그래픽 문서](https://doc.qt.io/qt-6/windows-graphics.html)에 설명된 Qt 배포본의 Mesa 라이브러리를 그대로 재사용합니다. VTK도 같은 라이브러리를 사용하도록 앱 전용 경로에서 불러옵니다.
