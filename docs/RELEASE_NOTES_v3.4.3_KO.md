# Prompt CAD Studio v3.4.3

같은 .pcad를 다시 열 때 앱을 종료했다는 이유로 형상·메시·간섭을 전부 재계산하던 비용을 줄였습니다. 부품이나 작업기록을 삭제하지 않습니다.

- 이전 전체 계산 결과를 사용자 설정 폴더의 인증된 JSON 캐시에 보관합니다. 전체 파일 바이트·입력 설계·앱 빌드·네이티브 런타임·표시 품질이 모두 일치해야 재사용합니다. 작업기록과 프로젝트 호환성 검증은 매번 유지합니다.
- 캐시 키는 로그인·Codex 인증과 분리된 새 무결성 키입니다. 캐시에서 코드나 pickle을 읽거나 실행하지 않습니다. 손상·잘림·불일치·캐시 쓰기 실패에서는 전체 계산으로 돌아가며 정상 프로젝트 열기를 막지 않습니다.
- 수동 저장 성공 후 현재 설계와 일치하는 계산 결과도 새 파일 바이트에 연결합니다. 저장 후 재열기에도 적용하고, 최신 부품 이름·색상을 반영합니다. 선택적 캐시 실패가 이미 완료한 프로젝트 저장을 실패로 바꾸지 않습니다.
- 관리하는 인증 캐시는 최대4개·총256MiB 범위입니다. 개별 캐시 한도는 프로젝트·부품·이력 제한이 아닙니다. 원본·이력·설정·로그인을 보존하며 정식 앱 경로 하나를 업데이트합니다.

실제 391부품·359기록·47.3MB 파일을 새 EXE의 서로 다른 프로세스에서 확인했습니다. 최초 전체 계산·캐시 작성은 약231초, 재열기 백엔드는 약14초였습니다. 전체 결과와 정리된 설계 해시가 일치했습니다. 실제 Windows 앱의 일반 열기 작업자·화면 경로에서는 약19초에 모델이 표시됐고, 391개 몸체·359개 기록·1,569,519개 삼각형과 실제 VTK 프레임·정상 종료를 확인했습니다. 설치된 정식 EXE로 실제 원본과 실제 사용자 캐시를 읽는 별도 검사도 약14초로 정상 완료됐습니다. 모든 수치는 이 파일과 실행 조건의 관찰값입니다.

실제391 자료에 네이티브 저장 메서드를 별도 이벤트루프 어댑터로 실행했습니다. 원본을 수정하지 않는 사본에서 이름 변경 기록1개를 추가해 360개 기록으로 저장하고, 기존359개 기록의 일치와 캐시 재열기를 확인했습니다. 기본 회귀163개와 저장·캐시 후속47개 검사가 통과했으며 두 범위에는 중복이 있어 합산하지 않습니다. 311개 포함 앱 모듈, 2,880개 재사용 런타임 파일, 새 업데이터를 검증했습니다. 마우스·클릭·키 입력 주입은 사용하지 않았습니다.

초기 화면 준비 중 최대 약6초의 이벤트 지연과 약2.14GiB의 최대 작업 집합은 남아 있습니다. 새 파일·다른 빌드·다른 표시 품질·유효한 캐시가 없는 파일은 첫 전체 계산이 필요합니다. 네이티브 BREP를 디스크 캐시로 복원하지 않으므로 첫 형상 편집·내보내기에서 원본 계산이 필요할 수 있습니다. 모든 조작·실제 더블클릭·모든 네이티브 오류·제작 또는 장비 안전을 승인한 결과는 아닙니다. SDK는 창 제목을 읽었으나 전체 창 캡처는 소유자 식별 오류로 실패했고, 실제 VTK 프레임은 별도로 확인했습니다.
